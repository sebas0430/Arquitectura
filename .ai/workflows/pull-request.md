# Workflow — Pull Request

Todo PR debe explicar:

- qué problema resuelve;
- requisito/tarea asociada;
- área afectada;
- contratos modificados;
- pruebas ejecutadas;
- riesgos;
- evidencias cuando aplique.

## Checklist

- [ ] Sale de `develop` si es feature/bugfix normal.
- [ ] No mezcla cambios no relacionados.
- [ ] Respeta límites del rol.
- [ ] No contiene secretos.
- [ ] Lint/format correcto.
- [ ] Pruebas relevantes pasan.
- [ ] Documentación actualizada si cambia comportamiento/arquitectura/contratos.
- [ ] Breaking changes identificados.
